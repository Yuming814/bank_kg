\# 零售银行 - 事件驱动产品推荐系统



\*\*项目周期\*\*: 2026.09  

\*\*技术栈\*\*: Python / NetworkX / PyTorch / GNN / Streamlit / Plotly  

\*\*数据规模\*\*: 500 客户 | 13 产品 | 903 购买关系 | 1200 行为事件 | 4 条推荐规则



\---



\## 一、项目背景



\### 1.1 为什么做这个项目



零售银行的产品推荐面临三大挑战：

1\. \*\*客户维度缺失\*\*：传统推荐只看"产品-产品"关联，忽略客户个性化需求

2\. \*\*事件驱动不足\*\*：市场事件（加息、股市波动）无法自动触发推荐

3\. \*\*可解释性差\*\*：黑盒模型无法解释"为什么推荐这个产品"



本项目构建了一个 \*\*"事件-产品-客户"三位一体\*\*的知识图谱，并结合\*\*规则引擎\*\*和\*\*图神经网络（GNN）\*\*两套推荐方案。



\### 1.2 核心目标



\- 从客户360°数据中构建画像节点

\- 用知识图谱打通"市场事件→产品→客户"的链路

\- 用规则引擎实现快速上线

\- 用 GNN 实现智能化推荐

\## 二、技术架构



\### 2.1 四层架构

┌─────────────────────────────────────────────────┐

│ 数据层 (Data Layer) │

│ 模拟数据：客户画像 + 产品 + 购买 + 行为 + 事件 │

├─────────────────────────────────────────────────┤

│ 图谱层 (Knowledge Graph Layer) │

│ NetworkX: 6 层节点（产品维度/市场范围/持仓/事件/客户/行为）│

├─────────────────────────────────────────────────┤

│ 推荐层 (Recommendation Layer) │

│ 规则引擎（4条规则）+ GNN（异构图神经网络） │

├─────────────────────────────────────────────────┤

│ 应用层 (Application Layer) │

│ Streamlit 交互式仪表盘 │

└─────────────────────────────────────────────────┘



\### 2.2 图谱 Schema



\*\*节点类型\*\*（14 类）：

\- 产品维度：AssetClass、GeographicScope、IndustryCategory、GoodsCategory

\- 市场范围：MarketScope

\- 产品层：FundProduct、HoldingItem、Issuer

\- 事件层：Event、EconomicIndicator、FundEvent、BehaviorEvent

\- 客户层：Customer、Institution



\*\*核心关系\*\*：

| 关系 | 说明 |

|------|------|

| `HAS\_ITEM` / `HAS\_ISSUER` | 产品持仓穿透 |

| `HAS\_EXPOSURE\_TO` | 产品暴露在市场范围下 |

| `ABOUT` | 事件影响市场范围 |

| `PREFERS` | 客户偏好市场范围 |

| `HOLDS` | 客户持有产品 |

| `PERFORMS` / `TARGETS` | 客户行为链路 |

| `TRIGGERS` | 客户触发资金事件 |

\## 四、推荐引擎设计



\### 4.1 规则引擎（4条规则）



| 规则 | 触发条件 | 推荐逻辑 |

|------|---------|---------|

| \*\*规则1：市场事件驱动\*\* | 央行加息/股市波动 | 事件→影响产品→风险匹配客户 |

| \*\*规则2：存款到期\*\* | 定期存款即将到期 | 到期资金→推荐替代产品 |

| \*\*规则3：行为驱动\*\* | 浏览产品但未购买 | 浏览→推荐相似产品 |

| \*\*规则4：闲钱理财\*\* | 闲钱 > 10万 | 闲钱→风险匹配产品 |



\*\*示例\*\*：

\- 事件：央行加息25个基点

\- 影响产品：招银货币基金

\- 推荐客户：100 个偏好 MS\_CN\_CASH 的稳健型客户



\### 4.2 GNN 异构图推荐



\*\*模型架构\*\*：

\- 客户/产品/事件分别做特征投影（64维）

\- 通过消息传递聚合邻域信息

\- 输出客户和产品的嵌入向量

\- 用内积计算匹配得分



\*\*训练目标\*\*：BPR（Bayesian Personalized Ranking）损失



\*\*评估结果\*\*：测试集 AUC > 0.7



\*\*Top 推荐产品\*\*：

1\. FP\_003（工银稳健债券基金）— 得分 2.8

2\. FP\_001（华夏科技成长基金）— 得分 1.9

3\. FP\_004（招银货币基金）— 得分 1.3

\## 五、技术难点与解决方案



| 难点 | 解决方案 |

|------|---------|

| 客户-产品多对多关系 | 用异构图而非表格建模 |

| 事件影响链路复杂 | 通过 MarketScope 中间层解耦 |

| 规则引擎僵硬 | 引入 GNN 自动学习高阶关系 |

| 冷启动问题 | 用 PREFERS 关系通过风险偏好匹配 |

| 数据隐私 | 全部使用模拟数据 |

\## 七、经验总结



\### 7.1 技术收获



1\. \*\*知识图谱建模\*\*：掌握了 6 层异构图的构建方法

2\. \*\*规则引擎\*\*：学会用 Cypher 风格遍历图谱做推荐

3\. \*\*GNN 推荐\*\*：实现了简化版异构图神经网络

4\. \*\*Streamlit 应用\*\*：快速构建交互式 Web 界面



\### 7.2 不足与改进方向



\- \*\*数据量小\*\*：仅 500 客户，需扩展到 1 万+

\- \*\*特征简单\*\*：未使用文本、序列等复杂特征

\- \*\*GNN 模型较浅\*\*：可升级为 HGT Transformer

\- \*\*未集成 LLM\*\*：可用 RAG-FLARKO 做可解释推荐
